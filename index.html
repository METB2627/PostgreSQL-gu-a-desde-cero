Introducción a las Bases de Datos y los SGBD

Conceptos básicos, tipos de SGBD y vías de conexión

1.1. ¿Qué es una base de datos?

Una base de datos es una colección organizada de información almacenada y accesible electrónicamente desde un sistema informático. Cuando esta información crece en volumen y complejidad, su diseño requiere técnicas formales de modelado (como el modelo entidad-relación).

🔵
INFORMACIÓN ADICIONALPiensa en una base de datos como un archivador digital gigantesco: en lugar de carpetas físicas, tenemos tablas con filas y columnas, con la ventaja de buscar y relacionar millones de registros en milisegundos.

1.2. ¿Qué es un SGBD?

El SGBD, también llamado DBMS (Database Management System — Sistema de Gestión de Bases de Datos), es el software intermedio que interactúa con usuarios, aplicaciones y la propia base de datos para capturar, organizar y analizar los datos. Incluye además las herramientas para su administración.

Al conjunto formado por la base de datos + el SGBD + las aplicaciones asociadas se le denomina sistema de base de datos.

1.4. Formas de conectar una aplicación a un SGBD

  1. Bases de datos embebidas: la conexión entre el programa y la base de datos es directa. Máxima velocidad, pero poca portabilidad entre SGBD.
  2. API (Application Programming Interface — Interfaz de Programación de Aplicaciones) genérica: estándar ODBC (Open Database Connectivity — Conectividad Abierta a Bases de Datos), muy usado en C, C++, C# y Visual Basic.
  3. API nativa orientada a objetos: en Java se usa JDBC (Java Database Connectivity — Conectividad a Bases de Datos desde Java), ya que ODBC resulta inadecuado al basarse en llamadas estilo C con punteros.
🔴
CRÍTICOUna conexión embebida directa es poco recomendable para aplicaciones que deban ser portables entre distintos SGBD.

Instalación y Configuración de PostgreSQL

Historia, características clave y puesta en marcha paso a paso

2.1. ¿Qué es PostgreSQL?

PostgreSQL, también conocido como Postgres, es un RDBMS (Relational Database Management System) libre y de código abierto, centrado en la extensibilidad y el cumplimiento del estándar SQL (Structured Query Language — Lenguaje de Consulta Estructurado).

🕰️ Breve historia

  • Nació como sucesor del proyecto Ingres, desarrollado en la Universidad de California, Berkeley, bajo el nombre POSTGRES.
  • En 1996 se renombra PostgreSQL para reflejar su soporte de SQL.
  • Tras una revisión en 2007, el equipo mantiene el nombre PostgreSQL, aceptando también el alias "Postgres".

2.2. Características principales

  • Transacciones con propiedades ACID (Atomicity, Consistency, Isolation, Durability — Atomicidad, Consistencia, Aislamiento y Durabilidad).
  • Vistas actualizables automáticamente y vistas materializadas.
  • Triggers (disparadores) y claves foráneas (foreign keys).
  • Procedimientos almacenados (stored procedures).
  • Es el SGBD por defecto de macOS Server; disponible para Windows, Linux, FreeBSD y OpenBSD.

2.3. Instalación paso a paso

Windows

  1. Descargar el instalador desde el sitio oficial.
  2. Ejecutar el asistente y seleccionar la ruta de instalación.
  3. Establecer la contraseña del superusuario postgres.
  4. Confirmar el puerto por defecto: 5432.
  5. Marcar la casilla para lanzar Stack Builder al finalizar.
🔴
PASO CRÍTICOEjecutar Stack Builder es obligatorio para instalar los drivers JDBC. En Stack Builder: Categorías → Database Drivers → pgJDBC.

Linux (Debian/Ubuntu)

bash
sudo apt update
sudo apt install postgresql postgresql-contrib
sudo systemctl start postgresql
sudo systemctl enable postgresql

macOS

bash
brew install postgresql
brew services start postgresql

Primeros Pasos con SQL: Definición de Datos (DDL)

Creación de bases de datos, tablas, tipos y restricciones

3.1. ¿Qué es SQL?

SQL (Structured Query Language) es el lenguaje estándar para interactuar con bases de datos relacionales. Se divide en subconjuntos:

SubconjuntoSignificadoEjemplos
DDLData Definition Language (Lenguaje de Definición de Datos)CREATE, ALTER, DROP
DMLData Manipulation Language (Lenguaje de Manipulación de Datos)SELECT, INSERT, UPDATE, DELETE
DCLData Control Language (Lenguaje de Control de Datos)GRANT, REVOKE
TCLTransaction Control Language (Lenguaje de Control de Transacciones)COMMIT, ROLLBACK

3.2. Creación de bases de datos y tablas

SQL
CREATE DATABASE "VTInstitute";

CREATE TABLE subjects (
    code   SERIAL PRIMARY KEY,
    name   VARCHAR(50) NOT NULL,
    year   INTEGER NOT NULL
);
🔵
INFORMACIÓN ADICIONALSERIAL es un pseudo-tipo propio de PostgreSQL que crea automáticamente una secuencia asociada a la columna, generando valores autoincrementales.

4

Manipulación de Datos (DML): Operaciones CRUD

Create, Read, Update, Delete

CRUD son las siglas de Create, Read, Update, Delete (Crear, Leer, Actualizar, Eliminar), las cuatro operaciones básicas sobre datos.

4.1. INSERT — Crear registros

SQL
INSERT INTO subjects (name, year)
VALUES ('DATA ACCESS', 2),
       ('DEVELOPMENT ENVIRONMENTS', 1),
       ('DATABASE MANAGEMENT SYSTEMS', 1),
       ('SERVICES AND PROCESSES', 2);
🟢
BUENA PRÁCTICANo es necesario indicar el valor de code porque es SERIAL; PostgreSQL lo generará automáticamente.

4.2. SELECT — Leer registros

SQL
SELECT * FROM subjects;

SELECT name, year FROM subjects
WHERE year = 1
ORDER BY name ASC;
CláusulaFunción
WHEREFiltra filas según una condición
ORDER BYOrdena el resultado
LIMITLimita el número de filas devueltas
DISTINCTElimina filas duplicadas
GROUP BYAgrupa filas para cálculos agregados
HAVINGFiltra grupos (junto a GROUP BY)

4.3. UPDATE — Actualizar registros

SQL
UPDATE subjects
SET year = 2
WHERE name = 'DEVELOPMENT ENVIRONMENTS';
🔴
CRÍTICOOlvidar la cláusula WHERE en un UPDATE provoca que TODAS las filas de la tabla se actualicen.

4.4. DELETE — Eliminar registros

SQL
DELETE FROM subjects
WHERE code = 5;
🔴
CRÍTICOIgual que con UPDATE, un DELETE sin WHERE borra TODOS los registros de la tabla.

PL/pgSQL y Procedimientos Almacenados

Funciones, procedimientos y retorno de conjuntos de datos

6.1. ¿Qué es PL/pgSQL?

PL/pgSQL (Procedural Language/PostgreSQL) es el lenguaje procedimental propio de PostgreSQL para escribir funciones y procedimientos almacenados ejecutados directamente en el motor.

Concepto¿Devuelve valor?Palabra clave
FunciónSí (valor o conjunto de filas)CREATE FUNCTION
ProcedimientoNo necesariamenteCREATE PROCEDURE

6.2. Estructura básica

PL/pgSQL
CREATE OR REPLACE FUNCTION function_name (arguments)
RETURNS return_datatype
LANGUAGE 'plpgsql'
AS $BODY$
DECLARE
    declaration;
BEGIN
    -- cuerpo de la funcion
    RETURN valor;
END;
$BODY$;

Ejemplo práctico: contar asignaturas por año

PL/pgSQL
CREATE OR REPLACE FUNCTION public.subjectsinyear(theyear integer)
    RETURNS integer
    LANGUAGE 'plpgsql'
AS $BODY$
DECLARE
    amount INTEGER;
BEGIN
    SELECT COUNT(*) INTO amount FROM subjects WHERE subjects.year = theyear;
    RETURN amount;
END;
$BODY$;

-- Invocacion
SELECT subjectsinyear(1);

6.3. Retorno de conjuntos: SETOF, CREATE TYPE y RETURNS TABLE

PL/pgSQL
CREATE OR REPLACE FUNCTION listofsubjects(theyear integer)
    RETURNS SETOF subjects
    LANGUAGE 'plpgsql'
AS $BODY$
BEGIN
    RETURN QUERY
        SELECT * FROM subjects WHERE year = theyear;
END;
$BODY$;
PL/pgSQL
CREATE TYPE subjects_with_courses AS (
    name   VARCHAR(50),
    course VARCHAR(90)
);

CREATE OR REPLACE FUNCTION public.subjects_and_courses(theyear integer)
    RETURNS SETOF subjects_with_courses
    LANGUAGE 'plpgsql'
AS $BODY$
DECLARE
    mysubject subjects_with_courses;
BEGIN
    FOR mysubject IN
        SELECT subjects.name, courses.name
        FROM subjects INNER JOIN courses ON subjects.course = courses.code
        WHERE year = theyear
    LOOP
        RETURN NEXT mysubject;
    END LOOP;
END;
$BODY$;

PostgreSQL como ORDBMS

Dominios, tipos compuestos, enumerados, arrays y herencia

7.1. ¿Qué es un ORDBMS?

Un ORD (Object-Relational Database) o ORDBMS (Object-Relational Database Management System — Sistema de Gestión de Bases de Datos Objeto-Relacional) soporta directamente conceptos de la POO (Programación Orientada a Objetos): objetos, clases y herencia, integrados en el esquema y en el lenguaje de consultas.

graph LR A[SGBD Relacional Puro] --> B[ORDBMS - PostgreSQL, Oracle] B --> C[OODBMS - Objeto puro]
Fig. 7.1 — Espectro Relacional ↔ Orientado a Objetos
🔵
INFORMACIÓN ADICIONALPostgreSQL es un entorno fuertemente tipado: el polimorfismo real requiere conversiones (casts) explícitas.

7.2. Abstracción y encapsulación de datos

Las vistas permiten crear una interfaz abstraída de los datos, independiente del almacenamiento físico. Con funciones es posible simular "campos calculados":

SQL
-- PostgreSQL transforma automaticamente:
SELECT e.name FROM employee e;
-- en:
SELECT name(e) FROM employee e;
🟡
ATENCIÓNEsta transformación solo ocurre con la referencia a la fila completa (e.name); SELECT name FROM employee no tiene el mismo efecto.

7.3. Polimorfismo: Dominios

SQL
CREATE DOMAIN posint AS integer CHECK (VALUE > 0);

CREATE TABLE mytable (id posint);

INSERT INTO mytable VALUES(1);   -- funciona
INSERT INTO mytable VALUES(-1);  -- falla (viola el CHECK)
🔴
CRÍTICOUn cast implícito mal diseñado puede insertar datos erróneos sin lanzar error: '2012-05-31' es una fecha válida, pero 2012-05-31 sin comillas se evalúa aritméticamente como 1976.

7.4. Tipos compuestos, enumerados y arrays

Tipos compuestos

SQL
CREATE TYPE inventory_item AS (
    name        text,
    supplier_id integer,
    price       numeric
);

-- Correcto, con parentesis:
SELECT (item).name FROM on_hand WHERE (item).price > 9.99;

Tipos enumerados (ENUM)

SQL
CREATE TYPE mood AS ENUM ('sad', 'ok', 'happy');

CREATE TABLE person (
    name         text,
    current_mood mood
);
INSERT INTO person VALUES ('Moe', 'happy');

Arrays

SQL
CREATE TABLE notes (
    noteDate DATE,
    lines    TEXT[]
);

INSERT INTO notes VALUES ('2021-09-08',
  ARRAY['Course beginning', 'Prepare a PPT file']);

SELECT noteDate, lines[1] FROM notes;
UPDATE notes SET lines[2] = 'Prepare a PPT file';
🟡
ATENCIÓNA diferencia de Java, en los arrays de PostgreSQL el primer elemento tiene índice 1, no 0.

7.5. Herencia de tablas

PostgreSQL permite que una tabla herede de otra, incluyendo herencia múltiple (a diferencia de Oracle, DB2 e Informix).

SQL
CREATE TABLE cities (
    code       int PRIMARY KEY,
    name       text,
    population float,
    elevation  int
);

CREATE TABLE capitals (
    state char(2)
) INHERITS (cities);

-- Solo ciudades (sin capitales)
SELECT name, elevation FROM ONLY cities WHERE elevation > 500;

-- Las claves no se heredan: hay que anadirlas
ALTER TABLE capitals ADD CONSTRAINT pk_capitals PRIMARY KEY (code);
🔴
CRÍTICOLos índices (incluida la clave primaria) NO se heredan automáticamente en PostgreSQL.

Transacciones y Buenas Prácticas

Propiedades ACID aplicadas a SQL y JDBC

9.1. ¿Qué es una transacción?

Una transacción es una unidad lógica de trabajo. Si tiene éxito, los cambios se confirman (COMMIT); si ocurre un error, se deshacen (ROLLBACK).

9.2. Propiedades ACID

PropiedadSignificadoExplicación
AtomicityAtomicidadTodo o nada
ConsistencyConsistenciaDe estado válido a estado válido
IsolationAislamientoTransacciones concurrentes no se interfieren
DurabilityDurabilidadLos cambios confirmados persisten tras fallos
flowchart TD Start([Inicio de transaccion]) --> Check{Saldo de A mayor o igual a 500?} Check -- No --> Rollback[ROLLBACK: cancelar operacion] Check -- Si --> Debit[Restar 500 a la cuenta A] Debit --> Credit[Sumar 500 a la cuenta B] Credit --> Commit[COMMIT: confirmar cambios] Rollback --> End([Fin]) Commit --> End
Fig. 9.1 — Ejemplo clásico: transferencia bancaria
🔴
CRÍTICOSin transacción, si el proceso falla entre la resta a A y la suma a B, el dinero "desaparece" del sistema.

9.3. Transacciones en SQL y JDBC

SQL
BEGIN;
-- Operaciones...
COMMIT;    -- Confirma los cambios
-- o bien:
ROLLBACK;  -- Deshace los cambios
Java
try (Connection conn = DriverManager.getConnection(url, user, password)) {
    conn.setAutoCommit(false);
    try {
        PreparedStatement st = conn.prepareStatement(
            "INSERT INTO courses(name) VALUES(?)",
            Statement.RETURN_GENERATED_KEYS);
        st.setString(1, "Computer Systems Administration");
        st.executeUpdate();

        ResultSet keys = st.getGeneratedKeys();
        keys.next();
        int courseCode = keys.getInt(1);

        PreparedStatement st2 = conn.prepareStatement(
            "INSERT INTO subjects(name, year, course) VALUES (?, ?, ?)");
        st2.setString(1, "CyberSecurity");
        st2.setInt(2, 2);
        st2.setInt(3, courseCode);
        st2.executeUpdate();

        conn.commit();
    }
    catch (SQLException ex) {
        conn.rollback();
    }
}
🔵
INFORMACIÓN ADICIONALStatement.RETURN_GENERATED_KEYS permite recuperar las claves autogeneradas (normalmente SERIAL) tras un INSERT.

Resumen Ejecutivo Final

Las ideas clave de todo el manual, condensadas

🎯 Ideas clave que debes recordar

  1. PostgreSQL es un RDBMS libre, multiplataforma y extensible que además ofrece capacidades de ORDBMS: tipos personalizados, herencia de tablas y polimorfismo controlado.
  2. SQL se organiza en subconjuntos claros: DDL, DML, DCL y TCL. Dominar CREATE, SELECT, INSERT, UPDATE, DELETE, JOIN y funciones de agregación es la base indispensable.
  3. Vistas, procedimientos almacenados (PL/pgSQL) y tipos avanzados acercan la lógica de negocio a los datos, mejorando seguridad, rendimiento y mantenibilidad.
  4. La conexión desde Java se realiza mediante JDBC: registrar el driver, formular la URL y crear la conexión. PreparedStatement y CallableStatement son la barrera principal contra la inyección SQL.
  5. Las transacciones (ACID) garantizan que operaciones compuestas se completen íntegramente o se reviertan por completo.
  6. La gestión correcta de recursos (try-with-resources, DbUtils) previene fugas de memoria y conexiones colgadas.
  7. Las herramientas gráficas (PgAdmin4, IntelliJ IDEA) aceleran el desarrollo, pero el conocimiento profundo de SQL sigue siendo imprescindible.

🏁 Mensaje Final
